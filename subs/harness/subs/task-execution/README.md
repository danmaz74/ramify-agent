# Task execution

Runs an authorized prepared attempt through the shared agent/session-store contracts. Managed runs, manual steps and standalone sessions reach `executePreparedTask` through their workflow adapter. The child owns actual session operations, preserving/fresh/continue/fork binding, unavailable-context fallback orchestration, equipment/tool/submission binding, packet framing and manifests, observations and transcripts, progress watchdogs and writer/process settlement.

`PreparedTask` supplies resolved context, limits, authority-independent task facts and recording destinations. `TaskExecutionPorts` supplies individual acceptance, preparation, outcome and settlement transitions, current-authority checks and workflow observations. It receives no Run, RunLog, mutex collection, live-session map, StepInputs, starting-input graph or LoadedPackage. Workflow owners retain scheduling, successor admission, semantic retry/completion, task/role/procedure selection, validators, authority and consultation/scratch policy. Their journal callbacks preserve atomic accepted writes and late-attempt fencing. The transcript writer cache lives here; callers can drain it without receiving the mutable map.

`TaskSessionOperations` owns immutable correlation and acceptance records plus the injected durable session store. It calls a lazy preparation callback returning the small `PreparedTaskPackage` only when constructing a new operation. A restored operation uses original recorded packets even when current prompt files are unavailable or invalid. Generic framing is identical for rendering and execution. Workflow `prompts/session-adapter.ts` resolves procedure/schema/environment policy and classifies historical inspectable shell effects; no autonomous scheduler is imported here.

Workflow policy supplies whether a progress watchdog applies. Review and reconciliation remain exempt from elapsed-silence stops; explicit cancellation, shutdown, actual failure and settlement remain effective. A settlement observation timeout never proves drainage. Missing optional context permits a fresh prepared successor only after authority and writer settlement allow it; workflow owners admit that successor.

Ordinary tests use scripted external answers with the configured process guard. The relocated native writer witness retains its exact three process-group claims and registration. Read-only transcript/projection APIs retain their original wire shapes and corruption/coverage behavior.
