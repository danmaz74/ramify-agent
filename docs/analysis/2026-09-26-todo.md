# To do after the self-explaining denials trial

**Date:** 2026-09-26. **Status:** ranked proposals without an identified
implementation at this review; recheck status before starting work. This is a
follow-up list, not an implementation plan or acceptance record.

The September 26 trial ended with no completed work item. Seven iterations
closed partial or unsuitable before its first accepted candidate; the required
work-item suite later found five failures that iteration gates had missed. The
run analysis is recorded at
`ramify-agent/docs/analysis/2026-09-26-self-explaining-denials-run-analysis.md`
in commit `c4af2a4e`. The role-by-role session review was an untracked draft in
the harness trial checkout when this list was written. Its recommendations
need review before becoming implementation contracts.

## Harness proposals, highest expected impact first

1. **Improve the contract engineer's interface design and impact discovery.**
   Investigation and replay experiments started; production changes remain
   unimplemented.
   The contract engineer owns the interface design. It must distinguish the
   required behavior from a chosen representation, investigate existing
   producers and consumers, and evaluate compatibility before proposing a
   contract. This includes fakes, typed fixtures, serialization paths and
   behavioral tests. A blocked edit must not end discovery at the first
   affected location. Report the design, affected owners, evidence and
   unresolved compatibility decisions together; the local architect uses
   that report to coordinate implementation under module scopes. Paths are
   evidence, not assignments of individual files. Compare the original and
   improved prompts from the first contract session's starting state, then
   address harness limitations separately. See the
   [contract-engineer investigation](2026-09-26-contract-engineer-replay.md).
   The [acceptance analysis](2026-09-26-contract-engineer-acceptance.md) adds
   concise prompt delivery, correction of repairable incomplete results in
   the same session, and harness-run tests with evidence of actual fake use.

2. **Select iteration checks from the files the candidate changed.** Include
   affected owners' tests and run declared scenarios wherever their feature
   files live, even when the assignment starts in another owner. Preserve the
   required full work-item gate. In the trial, two iteration gates ran no
   scenarios and the later full gate found five failures.

3. **Check decisions and summaries against primary evidence.** Before deciding
   what to do after a failed gate, inspect its decisive failure lines and full
   log. Give reconciliation the scenario lifecycle rule and each scope review's
   actual result. Verify claimed test coverage against executed test titles,
   and require a `fixed` disposition to identify the remedy it verifies. An
   unavailable review remains a visible coverage gap in the work-item
   decision. The gate-brief formatting fix already exposes failure output;
   this item concerns the decisions made from that evidence.

4. **Let the last reconciliation round request a bounded correction.** Review
   the rule that forbids all repairs in the final round and sends `unresolved`
   to the same gate path as `complete`. A claimed repair must correspond to a
   performed, verified change; otherwise the finding stays open. Keep the
   finite round bound and required gate.

5. **Avoid repeating a failed full gate on an unchanged tree.** Reuse the
   recorded failure for the same tree and check definition unless a retry
   tests a named transient-failure hypothesis or a specific diagnostic
   question. The trial reran the same full suite on the same commit and got
   the same five failures.

6. **Remove redundant session setup.** Review whether design-review
   orientation sessions can be dropped when forks reread the guidance anyway.
   Supply each fork's actual working directory in its prompt and keep fork
   prompts and tools stable enough for cache reuse. This addresses repeated
   path errors and context spent on orientation that the reviews did not use.
